1. INTRODUCTION                                  *atlassian-introduction*

An opinionated Neovim interface for Atlassian Jira and Confluence Cloud.
View and edit issues and wiki pages directly inside Neovim using an
ADF projection engine that renders clean text with extmarks.

Features:

  - ADF projection editor: clean text buffer over ADF tree
  - Outline board with hierarchy, urgency heatmap, grouping
  - Fuzzy search via snacks.nvim pickers
  - Draft-first editing: `:w` saves locally, `<leader>ss` submits
  - Offline queue for write operations
  - Markdown-style input shortcuts in editor
  - Image and PDF preview (image.nvim / snacks.image)
  - Protocol handlers: `:edit jira://PROJ-123`
  - Slash commands (blink.cmp integration)

2. SETUP                                               *atlassian-setup*

Environment Variables ~
                                                  *atlassian-setup-env*

The plugin reads credentials from environment variables.
Confluence variables fall back to the corresponding Jira variable
when not set.

  Variable              Fallback          Description ~
  JIRA_URL              -                 Jira instance URL
  JIRA_EMAIL            -                 Jira account email
  JIRA_API_TOKEN        -                 Jira API token
  JIRA_PROJECT          -                 Default project (optional)

  CONFLUENCE_URL        JIRA_URL          Confluence instance URL
  CONFLUENCE_EMAIL      JIRA_EMAIL        Confluence account email
  CONFLUENCE_API_TOKEN  JIRA_API_TOKEN    Confluence API token
  CONFLUENCE_SPACE      -                 Default space (optional)

Lua Setup ~
                                                  *atlassian-setup-lua*

Alternatively, pass credentials via setup().  Read tokens from
environment variables — never hardcode API tokens as literal
strings in your config (they will end up in version control).
>lua
    require("jira-interface").setup({
      auth = {
        url   = "https://yoursite.atlassian.net",
        email = os.getenv("JIRA_EMAIL"),
        token = os.getenv("JIRA_API_TOKEN"),
      },
      default_project = "PROJ",
    })

    require("confluence-interface").setup({
      auth = {
        url   = "https://yoursite.atlassian.net/wiki",
        email = os.getenv("CONFLUENCE_EMAIL"),
        token = os.getenv("CONFLUENCE_API_TOKEN"),
      },
      default_space = "SPACE",
    })
<

Configuration Options ~
                                                  *atlassian-setup-options*

All keys are optional; defaults shown.  Pass only overrides to setup().

  cache_ttl        300       Cache time-to-live (seconds)
  max_results      500       Max issues fetched per query
  since            "-365d"   Only issues created since; nil disables
  types            ...       lvl1..lvl4 issue-type hierarchy
  statuses         ...       Statuses for transition flows

  acceptance_criteria_names  { "acceptance criteria" }
                             Name fragments used to auto-discover the
                             Acceptance Criteria field (all words must
                             appear in the field name). No custom_fields
                             entry is required for it.

  custom_fields    {}        heading -> field ID(s). Only needed for
                             non-rich-text fields; rich-text fields are
                             auto-discovered by name.

board.* options:

  workable_jql     nil       Defines the "workable" set for the status
                             bar; nil counts leaf nodes. The bar always
                             counts the full fetched set, independent of
                             done_filter.
  done_filter      "leaves"  Which done issues to hide from the outline:
                             "none" (show all), "trees" (hide only
                             fully-done trees), "leaves" (also hide done
                             leaf items and fully-done subtrees anywhere).
  involvement_sections ...   Bottom sections for issues where a user-valued
                             custom field is you but you are not the
                             assignee. List of { name, match = {substrings} };
                             fields are auto-sensed and join the first
                             matching section. Default: Reviewing (review),
                             Additional Assignees (additional, assignee).
  type_icons       ...       Per-type glyphs in the outline.
  epic_kinds       ...       label -> { name, icon, hl }. Drives kind
                             badges and `gk` grouping (Pillar / Shape Up
                             Goal / Operational). {} disables.
  cycle_pattern    "SU%d+/%d+"
                             Lua pattern for the Shape Up cycle id
                             (summary, then fix versions). Drives cycle
                             tags and `gc` grouping. nil disables.
  rules            {}        Issue rules: named boolean predicates over
                             an issue, usable by ANY board concept (not
                             just readiness). id = function(node) -> bool;
                             node.issue is the JiraIssue, node.children are
                             child nodes. Custom ids override built-ins.
                             Built-in ids: description, acceptance_criteria,
                             child_task, fix_version, epic_link, assignee.
  readiness        ...       Definition-of-Ready overlay (checkmark
                             ready / shaping) — one consumer of board.rules.
                             readiness.enabled toggles it.
                             readiness.levels[N] lists the rule ids that
                             must ALL pass for level N. See the README
                             "Issue Rules" section for details.

display.*, image.*, math.* control the editor windows, image/PDF
preview, and LaTeX macros respectively; see the README for their
full shape and defaults.

3. JIRA INTERFACE                                        *atlassian-jira*

COMMANDS                                        *atlassian-jira-commands*

Board ~

  :JiraBoard [project]        Open outline board (my work)
                              Use `gq` inside the board to switch
                              queries (assigned, created, epics,
                              team workload, due dates, custom JQL)
  :JiraMe                     Alias for :JiraBoard

Search ~

  :JiraSearch                 Fuzzy search across all issues
  :JiraSearchEdit             Search and edit an issue

Common ~

  :AtlassianSubmit            Submit current draft buffer to remote
                              (same as `<leader>ss`)

Issue Management ~

  :JiraView [key]             View issue (projected editor)
  :JiraEdit [key]             Edit issue (projected editor)
  :JiraTransition [key]       Change issue status
  :JiraStart [key]            Move issue to In Progress
  :JiraDone [key]             Move issue to Done
  :JiraReview [key]           Move issue to In Review
  :JiraCreate [type]          Create a new issue
  :JiraQuick <summary>        Quick-create with a one-liner
  :JiraComment [key]          Add a comment (default action)
  :JiraComment add [key]      Add a comment to an issue
  :JiraComment edit [key]     Pick and edit a comment
  :JiraComment delete [key]   Pick and delete a comment
  :JiraLink [key]             Add an issue link (default action)
  :JiraLink add [key]         Add an issue link
  :JiraLink delete [key]      Pick and delete an issue link

Filters ~

  :JiraFilter save <name>     Save current filter
  :JiraFilter load <name>     Load a saved filter
  :JiraFilter list            List all saved filters
  :JiraFilter delete <name>   Delete a saved filter

Other ~

  :JiraTodoToIssue [opts]     Convert TODOs to issues
                              Options: buffer, project

Offline ~

  :JiraQueue                  Show offline queue
  :JiraSync                   Sync queued operations

Utility ~

  :JiraClearCache             Clear local cache
  :JiraRefresh                Refresh current view
  :JiraStatus                 Show connection status
  :JiraHelp                   Show help summary
  :JiraFields [key]           Inspect fields on an issue
  :JiraTypes [project]        List issue types
  :JiraDebug [key]            Debug information

  Navigation ~

  zo            Expand (open fold)
  zc            Collapse (close fold)

  zM            Collapse all

  Actions ~

  Key           Action ~
  e             Edit issue (projected editor)
  t             Transition (change status)

  Grouping ~

  Key           Action ~
  gs            Group by status
  ga            Group by assignee
  gk            Group by epic kind (Pillar/Shape Up Goal/Operational)
  gc            Group by Shape Up cycle (e.g. SU1/26)
  gi            Group by priority (Highest → Lowest)
  gd            Group by due date
  gt            Group by type
  gn            No grouping

  Other ~

  Key           Action ~

  ?             Show help

EDIT BUFFER KEYMAPS                 *atlassian-edit-keymaps*

These mappings are available in projected edit buffers
(Jira and Confluence):

  Structural ~

  Key           Action ~
  <CR> (insert) Split paragraph / new list item
  <BS> (insert) Merge with previous (at col 0)
  J             Join adjacent paragraphs
  <CR> (normal) Toggle task checkbox
  >>            Indent list item
  <<            Outdent list item
  ]c / [c       Next / previous table cell

  Mark Toggling (visual mode) ~

  Key           Action ~
  <leader>b     Toggle bold
  <leader>i     Toggle italic
  <leader>c     Toggle code
  <leader>s     Toggle strikethrough
  <leader>k     Toggle link (prompts for URL)

  Insert Blocks (normal mode) ~

  Key           Action ~
  <leader>ih    Insert heading (prompts for level)
  <leader>ic    Insert code block (prompts for language)
  <leader>it    Insert table (prompts for rows×cols)
  <leader>ip    Insert panel (select type)
  <leader>il    Insert bullet list

  Markdown Shortcuts (insert mode) ~

  Typing these at the start of a line converts the paragraph:

  Input         Result ~
  # text        Heading 1
  ## text       Heading 2 (up to ######)
  - text        Bullet list item
  * text        Bullet list item
  1. text       Ordered list item
  - [ ] text    Task item (TODO)
  - [x] text    Task item (DONE)
  > text        Blockquote
  ---           Horizontal rule
  ```           Code block

  Submit ~

  Key           Action ~
  :w            Save draft locally (no API call)
  <leader>ss    Submit changes to remote API
  :AtlassianSubmit  Same as `<leader>ss`

The winbar shows "DRAFT" while unsaved, "SAVED" after submit.

5. EDITOR                                          *atlassian-editor*

OVERVIEW                                     *atlassian-editor-overview*

The plugin uses an ADF (Atlassian Document Format) projection
engine.  The ADF tree is the source of truth, held in memory as
a Lua table.  The buffer contains only clean, editable text.
All visual decoration (headings, bold, lists, tables, panels)
is rendered via Neovim extmarks.

This replaces the legacy CSF/XML editing approach entirely.

---------------------------------------------------------------------------
RENDERING                                    *atlassian-editor-rendering*

Each ADF node type renders to clean text with extmark styling:

  Node Type       Display ~
  heading         Plain text + heading highlight + sign icon
  paragraph       Word-wrapped at ~100 chars
  bulletList      Bullet prefix via inline virtual text
  orderedList     Number prefix via inline virtual text
  taskList        Checkbox ([ ] / [x]) via inline virtual text
  codeBlock       Bordered box with language label
  table           Row-per-line, │ delimiters, box-drawing borders
  blockquote      ▎ prefix with quote highlight
  panel           Icon + colored left bar (info/note/warning/tip)
  rule            ━━━ horizontal line
  mediaSingle     [image: name] placeholder
  mention         @name with link highlight

Text marks (bold, italic, code, link, strikethrough) are shown
via extmark highlights — no XML tags visible.

---------------------------------------------------------------------------
IMAGE & PDF PREVIEW                          *atlassian-editor-images*

Images and PDF attachments can be previewed in a floating window.
Supports both `3rd/image.nvim` and `snacks.image` backends
(auto-detected).

  Key   Action ~
  K     Preview image or PDF first page at cursor

PDF preview converts the first page to PNG via ImageMagick
(`magick` or `convert`).  Results are cached locally at:
>
    stdpath("cache") .. "/atlassian/images"
<

6. CONFIGURATION                              *atlassian-configuration*

JIRA CONFIGURATION                             *atlassian-jira-config*

Pass a table to `require("jira-interface").setup()`.  All keys
are optional; the defaults are shown below.

>lua
    require("jira-interface").setup({

      -- Authentication
      auth = {
        url   = nil,  -- string: Jira instance URL
        email = nil,  -- string: account email
        token = nil,  -- string: API token
      },

      -- Project
      default_project = nil,  -- string: default project key

      -- Data
      cache_ttl   = 300,      -- number: cache lifetime (seconds)
      max_results = 500,      -- number: max issues per query
      since       = "-365d",  -- string: JQL relative date filter
      data_dir    = nil,      -- string: override data directory

      -- Issue type hierarchy (lvl1 = top)
      types = {
        lvl1 = { "Epic" },
        lvl2 = { "Feature", "Bug", "Issue" },
        lvl3 = { "Task" },
        lvl4 = { "Sub-Task" },
      },

      -- Statuses recognised by transition helpers
      statuses = {
        "To Do", "In Progress", "In Review",
        "Blocked", "Done",
      },

      -- Board
      board = {
        workable_jql = nil,  -- string: JQL predicate for status bar
                             -- e.g. 'issuetype in ("Task", "Bug")'
                             -- nil = count leaf nodes (no children)
      },

      -- Custom fields: map section heading → Jira field ID. Only needed for
      -- non-rich-text fields; rich-text fields (incl. Acceptance Criteria) are
      -- auto-discovered by name. See |atlassian-setup-options|.
      custom_fields = {
        ["Reviewer"] = "customfield_10030",
      },

      -- Display
      display = {
        mode         = "float",    -- string: see |atlassian-display-modes|
        width        = "80%",      -- string|number
        height       = "80%",      -- string|number
        border       = "rounded",  -- string: border style
        wrap         = true,       -- boolean: line wrap
        linebreak    = true,       -- boolean: break at word boundary
        conceallevel = 2,          -- number: 0-3
        cursorline   = true,       -- boolean: highlight cursor line
      },

      -- Image preview
      image = {
        enabled       = true,          -- boolean
        max_file_size = 2 * 1024 * 1024,  -- number: bytes (2 MB)
        auto_preview  = false,         -- boolean: preview on hover
        cache_dir     = nil,           -- string: override cache dir
      },

      -- Math rendering
      math = {
        enabled      = true,         -- boolean
        block_macro  = "mathblock",  -- string: macro name
        inline_macro = "mathinline", -- string: macro name
        inline_param = "body",       -- string: parameter name
      },
    })
<

CONFLUENCE CONFIGURATION                  *atlassian-confluence-config*

Pass a table to `require("confluence-interface").setup()`.  The
structure mirrors Jira configuration.  All keys are optional;
the defaults are shown below.

>lua
    require("confluence-interface").setup({

      -- Authentication
      auth = {
        url   = nil,  -- string: Confluence instance URL
        email = nil,  -- string: account email
        token = nil,  -- string: API token
      },

      -- Space
      default_space = nil,  -- string: default space key

      -- Data
      cache_ttl   = 300,  -- number: cache lifetime (seconds)
      max_results = 100,  -- number: max pages per query
      data_dir    = nil,  -- string: override data directory

      -- Display (same options as Jira)
      display = {
        mode         = "float",
        width        = "80%",
        height       = "80%",
        border       = "rounded",
        wrap         = true,
        linebreak    = true,
        conceallevel = 2,
        cursorline   = true,
      },

      -- Image preview (same options as Jira)
      image = {
        enabled       = true,
        max_file_size = 2 * 1024 * 1024,
        auto_preview  = false,
        cache_dir     = nil,
      },

      -- Math rendering (same options as Jira)
      math = {
        enabled      = true,
        block_macro  = "mathblock",
        inline_macro = "mathinline",
        inline_param = "body",
      },
    })
<

---------------------------------------------------------------------------
DISPLAY MODES                                  *atlassian-display-modes*

The `display.mode` option controls how content buffers are
opened.

  Mode      Description ~
  float     Floating window (default)
  vsplit    Vertical split
  split     Horizontal split
  tab       New tab page
  buffer    Current buffer

---------------------------------------------------------------------------
DIMENSIONS                                   *atlassian-display-dimensions*

The `display.width` and `display.height` options accept either
an absolute number or a percentage string:

  Value       Meaning ~
  80          80 columns (or rows)
  "80%"       80% of the editor width (or height)
